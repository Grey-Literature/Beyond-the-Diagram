Back to the Authentication vs. Authorization trailhead

The core distinction is simple to state and easy to blur under pressure: authentication asks "are you who you say you are," authorization asks "given that, are you allowed to do this." Most real tickets that look like one are actually the other — or a third thing entirely.

Windows has a third category: account state

Locked out, expired password — genuinely neither an authentication nor an authorization failure, but almost always misread as "wrong password" anyway. That misreading has a sharp cost with lockouts specifically: retrying doesn't test anything once an account is locked, it just extends the lockout window further.

RADIUS: the client learns nothing

A flat "Access-Reject" is the sharpest real-world example of trust-boundary flattening . The server-side log disambiguates what the client never sees:

  • Event ID 6273, Reason Code 16 — authentication failure (bad credentials)
  • Event ID 6273, Reason Code 65 — authorization failure (valid credentials, but policy denies network access)

Same client-visible message, opposite root causes, opposite fixes.

HTTP's numbers actively mislead you

401 "Unauthorized" actually means not authenticated. 403 "Forbidden" is the one that actually means authorization failure. Reading the English word carefully isn't enough here — the number means something different from what the word implies, and only knowing the convention resolves it.

File shares stack two authorization layers

NTFS permissions and share permissions are independently applied, and the more restrictive of the two always wins. Checking only one and declaring victory is an easy, common mistake.

The real bottleneck: teaching a tech to read

Across all of the above, the actual failure mode is rarely ignorance of these definitions — it's pattern-matching on a keyword like "denied" or "failed" and jumping straight to a remembered fix instead of parsing the specific string in front of you. That's the whole reason Classification Drills exist as their own exercise type here, separate from a full Case.
